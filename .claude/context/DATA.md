## Оффер в YML (это и есть размеченная часть / gold)
```json
{"@id": "30055584", "@available": "true", "vendor": "Chieftec", "model": "AF-0925S",
 "name": "Вентилятор для компьютера Chieftec AF-0925S", "categories": {"categoryId": "6128"},
 "param": [{"@name": "Ширина", "#text": "80 - 120 мм"},                     <- бакет фильтра
           {"@name": "Ширина_search", "@unit": "мм", "#text": "90"},          <- точное значение
           {"@name": "Продавец", "#text": "М.Видео"},                         <- сегмент продавца
           {"@name": "Цвет_search", "#text": "черный"}, ...]}
```
- `vendor` → бренд, `model` → модель, `param[]` → характеристики. У одного атрибута бывает пара «фильтровый бакет» и `<имя>_search` (точное значение с `@unit`).
- Служебные параметры (`Потратить бонусы`, `Продавец`, `Подборки`, гарантия и т.п.) — не характеристики товара.
- Join: `offer.@id` ↔ `sku_desc.sku_id` ↔ `query_clicks.sku_id`.

## Что считаем входом и эталоном
- **Вход (Card)**: `title` + очищенное от HTML `description` из `sku_desc` (+ `seller_attrs`, если в описании есть блок «Характеристики:»).
- **Эталон (gold)**: `vendor`/`model`/`param` оффера, приведённые к каноническим атрибутам нашей таксономии.
- Метрики считаем на holdout, который не трогаем при настройке правил.

### Что важно для извлечения и оценки
- **Gold есть у 20% карточек**, и это в основном карточки без блока «Характеристики» → на эталоне меряем извлечение
  из title + описания; разбор seller_attrs важен для хвоста маркетплейса (cold start), но почти не покрыт эталоном.
- **Значительная часть эталона отсутствует в тексте** (диагональ смартфона в тексте у 34–51%, батарея у 50%, цвет iPhone
  у 12%) — recall надо считать по «извлекаемому» эталону (значение есть в тексте) и отдельно сообщать покрытие,
  иначе метрика штрафует за то, чего в карточке нет (а LLM будет соблазн «выдумать»).
- Имена параметров зависят от категории, пары «точное/бакет» бывают с разными именами: смартфоны «Встроенная память
  (ROM)» (точное, `1024 ГБ`) vs «Встроенная память» (бакет `1 ТБ`), «Диагональ» (`6.7`, unit `"`) vs «Диагональ экрана»
  (`6.6" и более`); ноутбуки: CPU — «Модель процессора» (`Core i5`, `M4`), а «Процессор» — длинная строка
  (`Apple M4 4.41 ГГц`, в тексте 4%); диагональ — `15.6"(39.6 см)`; накопитель — «Объём SSD» (`512 ГБ`).
- **iPhone — отдельный лист (914)**: ёмкости батареи в фиде почти нет (fill 8%), цвет — «Цвет производителя»
  по-английски (90%: `Blue`, `Desert Titanium`), а в заголовках тоже английские цвета → нужен словарь цветов RU/EN.
- Заголовки маркетплейса шумные: дубли («Смартфон Apple Смартфон Apple iPhone 17 Pro…»), хвост « -», RAM/ROM в виде
  `12/256GB`; заголовок совпадает с `offer.name` у 79,8%.
- Служебные параметры фида помечены `is_service` (Продавец, Потратить бонусы, Подборки, Топ коллекция, Акции, Гарантия*).

- **Эталон у 20,5% карточек (241 355), но на них 93,2% кликов поиска**; 74,8% карточек (880 632) — только текст
  (нет ни оффера, ни категории), ещё 4,7% — категория по `seo_id` кликов.
