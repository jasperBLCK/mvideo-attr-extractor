# Как выиграть кейс (71 команда, 1 место = 300 000 ₽)

## Главный инсайт про оценку
5 из 8 критериев (25 из 40 баллов) ставит **LLM-ревьюер, читающий репозиторий** (`main` в Gitea, зачётный прогон 23.10,
ежедневные прогоны 17–23.10 06:00–10:00). Он сверяет репо с требованиями кейса. Значит:
- каждое требование кейса должно иметь **явное, легко находимое доказательство** (файл, команда, цифра);
- README — главная страница для ревьюера: матрица «требование → где реализовано → метрика», быстрый старт, результаты;
- никаких «заглушек», TODO и синтетики, выдаваемой за результат; честные цифры на реальном gold.
Оставшиеся 15 баллов — жюри на финале: продуктовая ценность, реалистичность внедрения, питч.

## Критерий → что делаем
| Критерий | Действия |
|---|---|
| 1. Соответствие задаче кейса | Все 6 артефактов по очевидным путям; гибрид правила → NER → LLM с таблицей «что даёт каждый шаг»; все ограничения (схема, справочники, заземление, порог, стоимость, справедливость) реализованы и названы теми же словами, что в кейсе; петля обратной связи |
| 2. Работоспособность | `make demo`/`attrx demo` и `docker compose up` работают из коробки на закоммиченном сэмпле реальных карточек; CI зелёный; тесты; `/api/health`; без сети и без LLM всё работает; LLM подхватывает `OPENAI_API_KEY`/`OPENAI_BASE_URL` с ВМ |
| 3. Качество результата | Реальные P/R/F1 по атрибутам на gold из каталога М.Видео (holdout, без подгонки), coverage, traffic-weighted F1 по реальным кликам, по категориям и сегментам; калибровка уверенности; precision ≥ 0.95 на auto-accept |
| 4. Техническая реализация и архитектура | Модульный пакет `attrx`, конфиги вместо хардкода, типизация (pydantic), тесты, ADR/архитектурные доки, диаграмма, кэш LLM, батч-API |
| 5. Понятность использования | README за 5 минут, CLI с `--help`, Swagger `/docs`, понятный UI модератора, скриншоты/GIF, примеры запросов |
| 6. Продуктовая ценность (жюри) | Перевод метрик в деньги: +N% карточек в фильтрах по атрибутам, которые реально ищут (из query_clicks), экономия часов модераторов |
| 7. Реалистичность внедрения (жюри) | On-prem LLM (данные не уходят), стоимость на 1000 карточек, латентность, план раскатки (shadow → auto-accept по порогу), мониторинг дрейфа, интеграция с PIM через API |
| 8. Питч (жюри) | Живое демо на :8000 + запасное видео, 10 слайдов, готовые ответы на вопросы про риски |

## Чем выделиться (дифференциаторы)
1. **Gold из реального каталога М.Видео**: YML-фид (546K офферов, 6 963 категории) с атрибутами `param` — честный эталон по категориям,
   а не ручные 20 карточек. Отдельно меряем «извлекаемый recall» (значение вообще есть в тексте?) — честность оценки.
2. **Трафик из реальных поисковых кликов** (31M строк query_clicks): какие атрибуты люди ищут в каждой категории → веса для
   traffic-weighted метрик и приоритета очереди модерации. Ни одна команда без этого не посчитает «пользу для покупателя».
3. **Distant supervision**: NER учится на спанах, найденных сопоставлением значений из каталога с текстом — бесплатная разметка на сотни тысяч примеров.
4. **Самообучающиеся алиасы и справочники**: маппинг ключей «Характеристики:» из описаний продавцов на атрибуты каталога и словари допустимых значений
   строятся из данных, а не руками → масштабируется на тысячи категорий (длинный хвост, cold start).
5. **Анти-галлюцинации, видимые глазами**: каждое значение с цитатой и подсветкой в тексте; отброшенные LLM-значения логируются.
6. **Калиброванная уверенность** (reliability diagram) и выбор порога по целевой точности → «X% атрибутов заполняются автоматически при precision 95%».
7. **Экономика**: стоимость на 1000 карточек у «только LLM» vs «гибрид» (доля вызовов LLM, кэш) — на наших замерах.
8. **Справедливость**: метрики по сегментам продавцов (М.Видео vs маркетплейс), по размеру категории (head/torso/tail), по длине описания.
9. **Generative UI** модератора: интерфейс собирается под запрос из безопасного набора компонентов.

## Риски для нас
- Синтетические метрики 1.0 в старом REPORT.md выглядят подозрительно — заменить реальными.
- Тяжёлые зависимости (torch) ломают «работоспособность» → ML-слой опционален, базовая установка лёгкая.
- Датасет 1.1 ГБ не лежит в репо → скрипт загрузки/подготовки + закоммиченный компактный сэмпл реальных карточек для демо и тестов.
- LLM-ключ организаторов есть только на ВМ → всё должно работать без LLM; LLM-слой проверен на локальной модели (Ollama).
