# Критерии оценки и как решение их закрывает

## Как устроена оценка
8 критериев по 0–5. Пять оценивает автоматическая проверка репозитория по требованиям кейса (последний коммит `main`
в Gitea; ежедневные прогоны 17–23.10, зачётный — 23.10), три — жюри на финале (продуктовая ценность, реалистичность
внедрения, питч). Отсюда рабочее правило команды: каждое требование кейса должно иметь проверяемое подтверждение в
репозитории — файл, команду или число, — а README должен вести к нему за один клик. Никаких заглушек и синтетики,
выдаваемой за результат.

## Критерий → чем подтверждаем
| Критерий | Подтверждение в репозитории |
|---|---|
| 1. Соответствие задаче кейса | 6 артефактов по очевидным путям; гибрид правила → NER → LLM с таблицей вклада каждого шага; все ограничения кейса (схема, справочники, заземление, порог, стоимость, справедливость) реализованы и названы так же, как в кейсе; петля обратной связи |
| 2. Работоспособность | `attrx demo` и `docker compose up` на закоммиченном сэмпле реальных карточек; CI; тесты; `/api/health`; без сети и без LLM всё работает; LLM подхватывает `OPENAI_*` с ВМ; `make verify` пересчитывает метрики правил |
| 3. Качество результата | P/R/F1 по атрибутам на эталоне каталога (holdout), покрытие, F1 с весом спроса по реальным кликам, разрезы по категориям и продавцам, калибровка, precision принятых ≥ 0,95 |
| 4. Техническая реализация и архитектура | модульный пакет, конфиги вместо хардкода, pydantic-контракты, тесты, архитектурные доки, кэш LLM, батч-API, мониторинг |
| 5. Понятность использования | README за 5 минут, CLI с `--help`, Swagger, понятный UI модератора со скриншотами |
| 6. Продуктовая ценность (жюри) | метрики в деньгах: +покрытие атрибутов, по которым реально ищут (query_clicks), экономия ручной модерации |
| 7. Реалистичность внедрения (жюри) | on-prem LLM, стоимость на 1000 карточек, тень → автопринятие по порогу, мониторинг дрейфа, интеграция через API/батч |
| 8. Питч (жюри) | живое демо на :8000 + запасное видео, презентация, готовые ответы про риски |

## Отличия решения
1. Эталон из реального каталога М.Видео (YML-фид, 241 355 карточек) и отдельная полнота по «извлекаемому» эталону.
2. Веса атрибутов из реальных поисковых кликов (30,99 млн) → метрика «качество с учётом трафика» и приоритет очереди модерации.
3. Distant supervision: NER учится на значениях каталога, найденных в тексте, — разметка без ручного труда.
4. Справочники из данных (бренды каталога с транслитерацией, enum-маппинг из пар «бакет/точное значение»).
5. Анти-галлюцинации, видимые в интерфейсе: у каждого значения цитата с подсветкой; значения только от LLM — всегда на проверку.
6. Калиброванная уверенность и порог под целевую точность.
7. Экономика гибрида на наших замерах против «LLM на каждую карточку».
8. Справедливость: одинаковые метрики для М.Видео и партнёров, head / torso / tail категорий.
9. Generative UI модератора из безопасного набора компонентов.

## Риски для команды
- Тяжёлые зависимости (torch) — ML-слой опционален, базовая установка лёгкая.
- Датасет 1,1 ГБ не в репозитории — скрипт загрузки и подготовки + закоммиченный сэмпл реальных карточек.
- Ключ LLM организаторов есть только на ВМ — всё работает без LLM, LLM-слой проверен на локальной модели.
