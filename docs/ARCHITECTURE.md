# Архитектура

## Контракт данных (src/attrx/schema.py)
- **Card** — id, title, description, seller_attrs, category (опционально).
- **Candidate** — предложение значения от экстрактора: value, raw (цитата), source (seller/rules/ml/llm/human), score.
- **AttributeValue** — итог: value, unit, display, confidence, status (accepted/review/missing), sources, evidence.
- **ExtractionResult** — category + уверенность, список атрибутов, llm_used, warnings.

## Шаги
1. **Категория** — из поля категории, иначе по ключевым словам (слова в названии весят больше). Не уверены → предупреждение, фолбэк generic.
2. **Продавец** — ключи продавца сопоставляются с атрибутами через aliases, значение нормализуется. Базовая уверенность 0.8, потому что продавцы ошибаются.
3. **Правила** — регулярки по числам с единицами и правдоподобными диапазонами по категориям, пары «8/256 ГБ», различение ОЗУ и накопителя, процессоры, поиск по справочникам с учётом рода и числа.
4. **Агрегация** — значения группируются; согласие источников повышает уверенность (noisy-OR), альтернатива снижает её на половину своей поддержки.
5. **LLM** — только для пустых, слабых (< LLM_ROUTE_THRESHOLD) или конфликтных атрибутов. Strict JSON schema, temperature 0, ответ обязан содержать дословную цитату. Кэш в SQLite, лимит LLM_MAX_CALLS.
6. **Заземление** — цитата есть в карточке и значение из неё следует. Иначе значение отбрасывается с предупреждением.
7. **Статус** — accepted при confidence ≥ CONFIDENCE_THRESHOLD без серьёзного конфликта, review иначе, missing если в тексте нет.
8. **Обратная связь** — правки модератора пишутся в feedback.jsonl; attrx learn добавляет синонимы в learned.yaml.

## Почему не «всё в LLM»
- Цена и латентность: большинство числовых атрибутов закрываются регулярками за микросекунды.
- Воспроизводимость: правила детерминированы, LLM-ответы кэшируются.
- Контроль галлюцинаций: LLM только предлагает значение, решение принимают проверка и порог.
- Работа без внешней сети: при LLM_ENABLED=false решение полностью рабочее.
