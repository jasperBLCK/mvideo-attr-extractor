# LLM-слой: только для «хвоста» и без выдуманных характеристик

**Коротко.** LLM в attrx — не основной экстрактор, а добор хвоста: её зовут только для атрибутов, которые атрибуты
продавца, правила со справочниками и NER не закрыли уверенно, и только если о них вообще что-то сказано в тексте.
Каждый ответ LLM проходит шесть уровней защиты от галлюцинаций, а без LLM решение работает полностью. На ВМ хакатона
LLM включается сама (ключ организаторов из `OPENAI_API_KEY`/`OPENAI_BASE_URL`), on-prem — Ollama или vLLM в контуре
М.Видео. Модель по умолчанию для локального запуска — `qwen3:4b-instruct`, выбрана замером на реальных карточках
(раздел 5): 100% валидного JSON, 99% цитат найдены в тексте дословно, точность заземлённых значений 95% (справочники —
98%, числа — 95%, строки — 88%), полнота по извлекаемому эталону 93%, 3 ГБ видеопамяти; на GTX 1060 — ~7 с на карточку
при извлечении всех атрибутов и ~3 с на вызов в гибридном режиме.

| Требование кейса | Как сделано | Где |
|---|---|---|
| Не выдумывать характеристики | схема вывода, справочники допустимых значений, дословная цитата, проверка «значение есть в тексте», порог уверенности | `src/attrx/extractors/llm.py`, `src/attrx/verify.py`, `src/attrx/confidence.py` |
| Стоимость: LLM на каждую карточку — дорого | гибрид: LLM только для слабых/пустых/конфликтных атрибутов и только если они упомянуты в тексте; кэш; лимиты; локальная модель | `src/attrx/pipeline.py`, `src/attrx/extractors/llm.py`, раздел 6 |
| Внедрение без VPN | любой OpenAI-совместимый endpoint: on-prem Ollama/vLLM, GigaChat, YandexGPT | `src/attrx/config.py`, `.env.example`, `docker-compose.yml` |
| Воспроизводимость | temperature 0, строгий JSON, SQLite-кэш ответов, бенчмарк одной командой | `attrx llm-bench`, `docs/llm_bench.json` |

## 1. Где LLM в пайплайне

```
карточка → категория → атрибуты продавца → правила + справочники → NER ──► всё закрыто уверенно? ──да──► результат
                                                                     │ нет: пусто / уверенность < LLM_ROUTE_THRESHOLD / конфликт
                                                                     ▼
                                 префильтр: атрибут вообще упомянут в тексте? (для чисел — с цифрой рядом)
                                                                     ▼ да
                                          LLM: только эти атрибуты, строгий JSON + дословная цитата
                                                                     ▼
              нормализация к справочнику → проверка заземления → уверенность и порог → каталог или модератор
```

Почему только хвост, а не «всё в LLM»:

- **Деньги и время.** Правила обрабатывают тысячи карточек в секунду на CPU, LLM — секунды на карточку.
  Атрибуты продавца и правила закрывают бренд, память, «8/256 ГБ» в названии — платить за это LLM бессмысленно.
- **LLM не извлечёт то, чего нет в тексте.** По EDA у смартфонов диагональ есть в тексте лишь у 34–51% карточек,
  ёмкость батареи — у 50%, цвет iPhone — у 12%. Спрашивать о них LLM бесполезно: заземлённого значения не будет,
  а соблазн «вспомнить» характеристику модели — будет. Префильтр `relevant_attrs` отсекает такие атрибуты:
  на 20 реальных карточках **−56% вызовов (18 → 8) и −61% времени при том же результате** (те же 3 найденных
  значения, те же 2 пойманные галлюцинации).
- **Контроль.** Правила детерминированы и объяснимы; LLM только предлагает значение, решение принимают проверка и порог.
- **Работа без сети.** `LLM_ENABLED=false` (или нет ключа) — решение полностью рабочее на правилах и NER.

## 2. Контракт против галлюцинаций

| Уровень | Что делаем | Что ловит |
|---|---|---|
| 1. Схема категории в промпте | для каждого атрибута: название, тип (число/строка/справочник/да-нет), единица и **справочник допустимых значений**; правило «нет в тексте или неоднозначно — `null`» | модель не придумывает поля и формат |
| 2. Строгий JSON | `response_format: json_schema` (strict), `temperature: 0`; у провайдеров без json_schema — откат json_object → без формата, разбор JSON из текста | невалидный ответ не попадает в пайплайн |
| 3. Дословная цитата | для каждого значения обязательна `evidence` — цитата из карточки; в схеме она идёт **перед** значением (сначала процитировать, потом нормализовать) | значения «из знаний модели» без опоры на текст |
| 4. Справочник | значение приводится к канону детерминированной нормализацией (`normalize.py`); вне справочника — отбрасывается и пишется в заметки как кандидат на пополнение справочника | «новые» цвета/бренды, опечатки |
| 5. Заземление | `verify.grounded`: цитата есть в тексте карточки, **и значение следует из цитаты** (число из цитаты, синоним из справочника в цитате) | подмену: цитата про 5,4″, а значение 6,7″ |
| 6. Только LLM — только на проверку | значение, которое предложила одна LLM, **никогда не принимается автоматически**: статус `review`, даже если цитата заземлена и уверенность высокая (`pipeline.UNVERIFIED_ONLY` → `Extractor._finalize`; тест `tests/test_grounding.py::test_llm_only_value_goes_to_review`). Если LLM подтверждает значение продавца, правил или NER, её голос повышает общую уверенность (noisy-OR), и значение может пройти калиброванный порог (0,70): правила с уверенностью 0,6 — на проверку, те же правила + LLM — принято (`::test_llm_corroborating_rules_can_be_accepted`) | значение «из головы модели» не попадает в каталог без второго источника или модератора |

Это не теория — уровень 5 в бенчмарке (раздел 5) отбросил, например:
«бренд OPPO, цитата „Смартфон POCO C85“», «диагональ 6,7, цитата „Дисплей смартфона имеет диагональ 5,4 дюйма“»,
«ёмкость 5000 мА·ч, цитата „Полного заряда хватает на срок до 30 часов…“», «цвет чёрный, цитата „Deep Blue“»,
«ёмкость 100%, цитата „емкость батареи - 100%“» (состояние батареи восстановленного телефона).
Все отброшенные ответы с цитатами — в `docs/llm_bench.json` (`rejected_by_verification`).

**Почему справочник не зашит в JSON-схему как `enum`** (клиент это умеет: `LLM_SCHEMA_ENUM=true`). Замер показал,
что жёсткий список провоцирует «вынужденный выбор»: для ноутбука Colorful модель выбрала «Apple», для «Starry Blue» —
«жёлтый». Без enum модель пишет значение как в тексте («POCO», «Colorful»), к канону («Xiaomi») его приводит наш
справочник синонимов, а неизвестное значение становится заметкой для пополнения справочника (петля обратной связи).
На финальном промпте без enum заземлено 93% против 92%, полнота 93% против 92% при той же точности 95%, а с enum
модель снова «выбрала» синий для цвета «сияющая звезда» (в справочнике это белый).

## 3. Провайдеры и подключение

Код один, провайдер меняется переменными окружения. Порядок поиска настроек (`src/attrx/config.py`):

1. `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` — явная настройка;
2. `OPENAI_BASE_URL` / `OPENAI_API_KEY` — **так ключ организаторов уже задан на ВМ хакатона**;
3. `LLM_LOCAL_URL` — «если локальная LLM запущена — использовать» (так настроен `docker compose`);
4. ничего — LLM выключена, работают правила и NER.

`LLM_ENABLED=auto` (по умолчанию) включает LLM, только если найден пункт 1–3; `true`/`false` — принудительно.
`LLM_MODEL=auto` (по умолчанию) — модель выбирается из `GET {base}/models` по списку предпочтений `LLM_MODEL_PREFERENCE`
(эмбеддинги, whisper и т.п. пропускаются); если список недоступен — запасное имя, и это видно в статусе
(`model_source: discovered | fallback | env`). Ключ `OPENAI_API_KEY` никогда не отправляется на чужой `LLM_BASE_URL`.

| Провайдер | Настройка | Когда выбирать |
|---|---|---|
| Ключ организаторов (ВМ) | ничего: `OPENAI_API_KEY` и `OPENAI_BASE_URL` уже в окружении; модель — из `/models` | демо и замеры на ВМ; лимит дневной (`LLM_DAILY_MAX_CALLS`, кэш) |
| Ollama on-prem | `LLM_BASE_URL=http://127.0.0.1:11434/v1`, `LLM_MODEL=qwen3:4b-instruct` | стенд, ноутбук с GPU от 4 ГБ, закрытый контур |
| vLLM on-prem | `LLM_BASE_URL=http://<gpu-сервер>:8000/v1`, `LLM_MODEL=Qwen/Qwen2.5-7B-Instruct`, `LLM_CONCURRENCY=8` | прод М.Видео: данные не покидают периметр, батчинг |
| GigaChat | через OpenAI-совместимый прокси gpt2giga: `LLM_BASE_URL=http://127.0.0.1:8090/v1`, `LLM_MODEL=GigaChat` | российское облако, без VPN |
| YandexGPT | `LLM_BASE_URL=https://llm.api.cloud.yandex.net/v1`, `LLM_MODEL=gpt://<folder>/yandexgpt-lite/latest`, `LLM_API_KEY=<API-ключ>` | российское облако, без VPN |

Наружу (для облачных провайдеров) уходит только текст карточки товара — персональных данных в нём нет.

Основные переменные (полный список с комментариями — `.env.example`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_ENABLED` | `auto` | auto / true / false |
| `LLM_MODEL` | `auto` | имя модели или выбор из `/models` |
| `LLM_RESPONSE_FORMAT` | `json_schema` | с чего начинать цепочку json_schema → json_object → none |
| `LLM_REASONING_EFFORT` | пусто | `none` отключает «размышления» у гибридных моделей (qwen3/qwen3.5 в Ollama) |
| `LLM_CONCURRENCY` | `0` (авто) | параллельных запросов: 1 для Ollama (одна GPU), 4 для удалённых API |
| `LLM_PREFILTER` | `true` | не спрашивать об атрибутах, о которых в тексте нет ни слова (для чисел — ни цифры рядом) |
| `LLM_MAX_INPUT_CHARS` | `3500` | длинное описание сокращается до предложений, где упомянуты нужные атрибуты (дословно — цитаты остаются в тексте) |
| `LLM_MAX_CALLS` / `LLM_DAILY_MAX_CALLS` | `5000` / `0` | лимит вызовов на процесс / на сутки (счётчик по дням хранится в кэше) |
| `LLM_CACHE` | `true` | SQLite-кэш ответов: повторный прогон бесплатен и воспроизводим |
| `LLM_FEW_SHOT` | `false` | пример ответа в промпте (+~250 токенов) |
| `LLM_SCHEMA_ENUM` | `false` | зашить справочник в json_schema (см. раздел 2) |

## 4. Надёжность клиента

`src/attrx/llm/client.py` — один клиент для всех OpenAI-совместимых API:

- **Строгий JSON с откатом.** json_schema → json_object → без формата; рабочий вариант запоминается, лишних запросов нет.
  Параметры, которые провайдер не знает (`reasoning_effort`, `temperature` у reasoning-моделей,
  `max_tokens` → `max_completion_tokens`), снимаются автоматически.
- **Понятные ошибки.** Нет соединения, таймаут, ключ не принят, 429 (дневной лимит), модель не найдена, карточка не
  помещается в контекст, ответ обрезан — у каждой ошибки подсказка, что поменять. Пайплайн превращает её в
  предупреждение карточки и продолжает на правилах.
- **Предохранитель.** После ошибки соединения LLM «отдыхает» `LLM_RETRY_AFTER` секунд: карточки не ждут таймаут по очереди.
- **`localhost` → `127.0.0.1`.** httpx (внутри openai SDK) без «happy eyeballs» сначала идёт на `::1`; если IPv6-loopback
  фильтруется (как на стенде команды), первый запрос ждал полный таймаут — замерено **63 с вместо 1,7 с**.
  Ollama и vLLM слушают IPv4, поэтому клиент сам ходит на `127.0.0.1`.
- **Параллельность.** `client.map(fn, items)` и `extractors.llm.extract_batch(jobs, tax, client)` держат в полёте
  `LLM_CONCURRENCY` запросов (семафор в клиенте), порядок результатов сохраняется.
- **Учёт стоимости.** `client.stats()`: вызовы, попадания в кэш, токены prompt/completion (из `usage`, иначе оценка по
  длине текста), латентность avg/p50/p95; суточный счётчик — `client.usage_today()`; перевод в рубли — `attrx.llm.cost`.
- **Статус для `/api/health` и UI.** `attrx.llm.status.llm_status(client=None, probe=True)` → `enabled`, `mode`,
  `source`, `provider`, `model` (+ откуда выбрана), `reachable`, `latency_ms`, `error`. Проверка — `GET /models` с
  таймаутом 2 с и кэшем 30 с; ключ в ответ не попадает. То же в консоли: `attrx llm-status`.

## 5. Бенчмарк on-prem: какая модель по умолчанию

**Стенд команды:** GTX 1060 6 ГБ (Pascal), CPU Pentium Gold G5400 (4 потока, **без AVX** — инференс на CPU непригоден,
модель обязана целиком помещаться в видеопамять), 31 ГБ RAM, Ollama 0.33.3.

**Методика** (`attrx llm-bench`, `src/attrx/llm/bench.py`): 30 реальных карточек из `data/sample/real_cards.jsonl` —
15 смартфонов (включая iPhone) и 15 ноутбуков; сценарий «LLM на каждую карточку» — все 6 атрибутов категории (худший
случай по стоимости); промпт и схема — как в проде; json_schema, temperature 0, без кэша, последовательно, модель заранее
загружена. Эталон — параметры оффера из YML-фида (поле `gold` таксономии).
*Цитата найдена* — доля возвращённых значений, чья цитата есть в тексте; *заземлено* — прошло нормализацию и
`verify.grounded`; *точность* — заземлённые значения против эталона; *полнота* — против эталона, который вообще есть
в тексте карточки (то, чего в тексте нет, LLM извлекать не должна).

Выводы:

- **По умолчанию — `qwen3:4b-instruct`** (Qwen3-4B-Instruct-2507, без «размышлений»). На финальном промпте точность и
  полнота на уровне 7B: 95% / 93% против 96% / 93% у `qwen2.5:7b-instruct`, при этом на 30% быстрее (6,9 против 9,9 с на
  карточку) и занимает 3,0 ГБ видеопамяти против 4,4 ГБ — рядом остаётся место для обучения NER, а 7B на 6 ГБ рядом с
  рабочим столом один раз не загрузилась (не хватило видеопамяти под буфер вычислений).
- **`qwen2.5:7b-instruct`** — выбор для выделенной GPU от 8 ГБ: больше значений проходит заземление (97% против 93%),
  точнее строки (91% против 88%).
- **Точность по типам** (qwen3:4b-instruct): справочники 52/53 = 98%, числа 60/63 = 95%, строки 21/24 = 88%.
  Подсказки формата для строк в промпте («модель — без бренда, памяти и цвета», «процессор — линейка и модель»)
  подняли точность строк с 67% до 88%, общую — с 91% до 95%. Оставшиеся ошибки чисел — расхождения текста и фида
  (в описании MacBook Air 15 «15,6 дюйма», в фиде 15,3), поэтому значение от одной LLM без подтверждения другим
  источником в каталог не идёт — только на проверку модератору (раздел 2, уровень 6).
- **qwen3.5:4b** — гибридная «думающая» модель: даже с `LLM_REASONING_EFFORT=none` на 57% медленнее и слабее на строках;
  **mistral 7B** тратит больше токенов на русский текст (1 280 против 1 102) и реже цитирует дословно (95%).
- **Vulkan против CUDA на Pascal.** Пакет Ollama в Arch собран без CUDA, а CUDA 13 не поддерживает Pascal, поэтому стенд
  работает на Vulkan-бэкенде (раздел 7). Официальная сборка с CUDA 12 даёт более быстрый префилл (≈450 против
  ≈250 ток/с), но более медленную генерацию (≈30 против ≈42 ток/с) — в сумме Vulkan на 15% быстрее (6,9 против 8,1 с).
- **Гибридный режим** (пайплайн, LLM только для хвоста, 20 реальных карточек): ~1 018 токенов промпта и ~49 токенов
  ответа на вызов, **3,1 с на вызов**.
- **Видеопамять.** qwen3:4b-instruct занимает 3,0 ГБ — рядом остаётся ~2 ГБ на обучение NER (rubert-tiny2).
  Модель выгружается через 10 минут простоя (`OLLAMA_KEEP_ALIVE=10m`) или сразу: `ollama stop qwen3:4b-instruct`.

## 6. Стоимость на 1000 карточек

Токены на вызов — из замеров выше: «LLM на каждую карточку» — 1 102 + 199 токенов (все атрибуты),
гибрид — 1 018 + 49 токенов (только слабые атрибуты, карточка в промпте та же). Токены посчитаны токенизатором Qwen
(≈2,7 символа на токен); у GigaChat и YandexGPT токенизаторы обучены на русском, так что для них это оценка сверху.
Цены — `config/llm_prices.yaml` (с источниками, на 14.10.2026, ₽ с НДС, синхронный режим; асинхронный у Сбера и Яндекса
вдвое дешевле). Расчёт — `attrx.llm.cost.per_1000_cards(client.stats(), n_cards)`.

**Доля карточек, где гибрид зовёт LLM: p = 0,31** — замер на holdout (`attrx report-real`): 205 запросов на 662 карточки подвыборки, строка «+ LLM · подвыборка LLM» в `submission/compare.json`; LLM спрашивают только о слабых атрибутах, которые упомянуты в тексте. Стоимость гибрида на 1000 карточек = (₽ на 1000 вызовов в гибриде) × p.

## 7. Стенд команды: как запущена локальная LLM

Ollama из пакета Arch (`/usr/bin/ollama`, 0.33.3) собрана только под CPU, а CPU стенда без AVX — генерация на нём
непригодна (частичная выгрузка 3 слоёв из 33 на CPU роняла скорость с 28 до 6 ток/с). Поэтому без root собран
пользовательский вариант с GPU:

- `~/.local/opt/ollama-attrx/` — копия `/usr/bin/ollama` и `/usr/lib/ollama` + Vulkan-бэкенд `libggml-vulkan.so`
  из пакета Arch `ollama-vulkan` той же версии 0.33.3 (7 МБ; Vulkan-драйвер NVIDIA уже есть в системе);
- **почему Vulkan, а не CUDA:** сборка Arch `ollama-cuda` использует CUDA 13, где Pascal (GTX 1060, sm_61) уже не
  поддерживается; официальная сборка Ollama с CUDA 12 (1,4 ГБ) работает, но на этой карте медленнее
  (8,1 против 6,9 с на карточку в бенчмарке: префилл быстрее, генерация медленнее) — её сняли после замера;
- модели — в общем каталоге `~/.ollama/models`; сервис — пользовательский юнит systemd:

```bash
systemd-run --user --unit=ollama-attrx -p Restart=on-failure \
  --setenv=OLLAMA_HOST=127.0.0.1:11434 --setenv=OLLAMA_VULKAN=1 --setenv=OLLAMA_KEEP_ALIVE=10m \
  --setenv=OLLAMA_NUM_PARALLEL=1 --setenv=OLLAMA_MAX_LOADED_MODELS=1 --setenv=OLLAMA_CONTEXT_LENGTH=4096 \
  --setenv=LLAMA_ARG_FIT_TARGET=512 ~/.local/opt/ollama-attrx/bin/ollama serve
systemctl --user status ollama-attrx        # состояние;  journalctl --user -u ollama-attrx — логи
systemctl --user stop ollama-attrx          # остановить и освободить GPU
```

`LLAMA_ARG_FIT_TARGET=512` — запас видеопамяти в МиБ при автоподборе слоёв: по умолчанию (1 ГБ) 7B-модель не
помещалась целиком и 3 слоя уходили на CPU, а при 128 МиБ она однажды не загрузилась, когда браузер и рабочий стол
заняли больше видеопамяти; qwen3:4b-instruct при 512 МиБ целиком на GPU. `OLLAMA_KEEP_ALIVE=10m` — через 10 минут простоя модель выгружается,
GPU свободна для обучения NER. Скачаны: `qwen3:4b-instruct` (по умолчанию), `qwen2.5:7b-instruct`, `qwen3.5:4b`,
`mistral`.

## 8. Рекомендуемая настройка

| Где | Настройка | Почему |
|---|---|---|
| ВМ хакатона | ничего не задавать: `LLM_ENABLED=auto` подхватит ключ организаторов; при желании `LLM_DAILY_MAX_CALLS` под дневной лимит | кэш, префильтр и гибрид экономят лимит, `attrx llm-status` показывает выбранную модель |
| Стенд с GPU 4–6 ГБ | Ollama + `qwen3:4b-instruct`, `LLM_CONCURRENCY=1`, `OLLAMA_KEEP_ALIVE=10m`, `OLLAMA_CONTEXT_LENGTH=4096` | лучший баланс качества и скорости в замере, 3 ГБ VRAM |
| `docker compose --profile llm up` | Ollama в контейнере, модель скачивается при первом старте (`LLM_LOCAL_MODEL`, по умолчанию `qwen3:4b-instruct`) | приложение находит её само через `LLM_LOCAL_URL` |
| Прод М.Видео | vLLM в контуре на сервере с GPU 24 ГБ (L4/A10), 7–8B instruct-модель, `LLM_CONCURRENCY=8–16`; либо GigaChat/YandexGPT по API | данные не покидают периметр; гибрид и префильтр держат долю LLM-вызовов низкой |

## 9. Как воспроизвести

```bash
attrx llm-status                                   # провайдер, модель, доступность
# on-prem: Ollama на этой машине
ollama pull qwen3:4b-instruct
LLM_BASE_URL=http://127.0.0.1:11434/v1 LLM_MODEL=qwen3:4b-instruct attrx demo --llm on
# бенчмарк на реальных карточках (data/sample/real_cards.jsonl): латентность, JSON, заземление, точность, ₽
attrx llm-bench --models qwen3:4b-instruct,qwen2.5:7b-instruct --n 30 --base-url http://127.0.0.1:11434/v1
```

Тесты LLM-слоя (без сети, SDK подменён): `pytest -q tests/test_llm*.py` — фолбэк на `OPENAI_*` и `auto`,
цепочка форматов JSON, учёт токенов и кэша, лимиты, предохранитель, промпт со справочниками, префильтр, стоимость.
