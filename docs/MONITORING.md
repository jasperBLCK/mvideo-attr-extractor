# Мониторинг дрейфа и петля дообучения

Кейс требует закрыть риск «дрейф: новые категории и формулировки» мониторингом и петлёй дообучения. В продакшене
эталона нет, поэтому качество отслеживается по косвенным сигналам в самих предсказаниях. Их сравнивают с эталонным
прогоном, точность которого измерена: это итоговые предсказания на holdout, `submission/predictions.jsonl`.
Сработавший порог даёт алерт с готовым действием: разобрать очередь, `attrx learn`, `calibrate`, `train-category`
или `train-ner --distant`.

Код — [src/attrx/monitor.py](../src/attrx/monitor.py), тесты — [tests/test_monitor.py](../tests/test_monitor.py).
Модуль читает только JSONL предсказаний и журнал решений модератора: ему не нужны `data/processed`, torch и LLM,
так что он работает где угодно, в том числе в CI.

## Запуск

~~~bash
attrx extract -i new_cards.jsonl                 # предсказания -> outputs/predictions.jsonl
attrx monitor -i outputs/predictions.jsonl --ref submission/predictions.jsonl   # = make monitor
attrx monitor ... --fail-on-alert                # для cron/CI: код 2, если есть алерты
attrx monitor ... -t psi=0.2 -t min_cards=100    # свои пороги
~~~

Результат печатается таблицей по категориям и пишется в `outputs/monitor.json`. В файле: `overall` и
`reference_overall` (сводка по всем карточкам), `per_category` (метрики, доли в потоке и в эталоне, дельты, алерты),
`category_shift` (PSI, JS, новые и пропавшие категории, новые листья каталога), `alerts` и `next_steps`,
`feedback` (решения модератора и кандидаты в синонимы).

## Что меряется

| Метрика | Как считается | Что значит рост или падение |
|---|---|---|
| `review_share` | доля слотов «карточка × атрибут» со статусом review (как `review_rate` в метриках) | больше ручной работы; источники спорят или уверенность упала |
| `missing_share` | доля слотов без значения | правила и NER не узнают новые формулировки и единицы |
| `mean_confidence` | средняя калиброванная уверенность найденных значений | калибровка разошлась с потоком |
| `conflict_share` | доля найденных значений с альтернативами (источники спорят) | например, новый партнёр с плохими полями продавца |
| `category_unsure_share` | доля карточек с предупреждением «категория определена неуверенно» | классификатор категории встретил незнакомые товары |
| `generic_share` | доля карточек вне таксономии (только по всем карточкам) | появились новые категории, которых нет в `config/taxonomy.yaml` |
| PSI и JS | сдвиг распределения категорий против эталона: PSI с долями, сглаженными снизу 1e-4; дивергенция Йенсена — Шеннона (log2, от 0 до 1) | сменился ассортимент: PSI < 0,1 — сдвига нет, 0,1–0,25 — умеренный, выше — сильный |
| `new_leaves` | листья каталога у карточек generic, которых нет в эталонном прогоне (топ-20) | кандидаты в новые категории таксономии; информационно, без алерта |
| `llm_share`, `llm_rejected_per_card` | доля карточек с вызовом LLM; значения LLM, отброшенные проверкой заземления, на карточку | растёт стоимость; модель чаще «додумывает» |
| `feedback` | решения из `outputs/feedback.jsonl`: подтверждено, исправлено, отклонено по категориям; сколько синонимов ждут подтверждения | движение петли обратной связи |

## Пороги по умолчанию

| Порог | Значение | Алерт, если |
|---|---|---|
| `review_share` | 0,20 | доля на проверке выше |
| `missing_share` | 0,60 | доля пустых слотов выше |
| `mean_confidence` | 0,75 | средняя уверенность ниже |
| `category_unsure_share` | 0,10 | доля карточек с неуверенной категорией выше |
| `generic_share` | 0,60 | доля generic выше (по всем карточкам) |
| `llm_share` | 0,50 | LLM вызывается больше чем для половины карточек (бюджет) |
| `delta` | 0,05 | review, missing, неуверенная категория или generic выросли относительно эталона больше чем на 5 п.п. |
| `delta_confidence` | 0,05 | средняя уверенность упала относительно эталона больше чем на 0,05 |
| `delta_llm_share` | 0,10 | доля карточек с LLM выросла больше чем на 10 п.п. |
| `psi` | 0,25 | сильный сдвиг распределения категорий |
| `min_cards` | 50 | в категориях с меньшим числом карточек алерты не поднимаются: на малых группах доли шумят |

Как выбраны абсолютные пороги. На итоговых предсказаниях holdout худшие категории выглядят так: review около 13%
(наушники), пустых слотов около 35% (холодильники), средняя уверенность около 0,87 (generic). По всем карточкам:
review 6,6%, missing 19,6%, уверенность 0,92. Пороги взяты с запасом, чтобы здоровый поток не шумел. Основной
сигнал дрейфа — относительные пороги (`delta*`, `psi`): они сравнивают поток с эталоном той же системы.
После первых недель теневого режима пороги стоит пересчитать по реальному потоку.

## Алерт → действие (петля дообучения)

| Сработало | Действие |
|---|---|
| `review_share` | разобрать очередь проверки (UI «Очередь»), затем `attrx learn`; если рост устойчивый — `attrx calibrate` на свежем dev |
| `missing_share` | посмотреть пустые слоты категории: новые формулировки и единицы добавить в правила и справочники; `attrx train-ner --distant` на свежем train |
| `mean_confidence` | `attrx calibrate` на свежем dev, проверить порог автопринятия |
| `category_unsure_share` | `attrx prepare` → `build-gold` → `train-category` (новые листья каталога в классификаторе) |
| `generic_share`, `new_leaves` | добавить категорию в `config/taxonomy.yaml`, затем `build-gold` → `build-dicts` → `calibrate` |
| `psi` | проверить `new_leaves` и неуверенную категорию; при необходимости `train-category`, пересчёт эталона и калибровки |
| `llm_share` | проверить `LLM_ROUTE_THRESHOLD` и бюджет `LLM_DAILY_MAX_CALLS` ([docs/LLM.md](LLM.md)); обычно рост LLM идёт следом за ростом missing |

Цикл целиком:

~~~
поток карточек ─► attrx extract ─► predictions.jsonl ─► attrx monitor (ежедневно; --fail-on-alert в cron)
                                        │                     │ алерт: что и где сдвинулось + действие
                                        ▼                     ▼
                        очередь модератора (UI) ─► feedback.jsonl ─► attrx learn
                                                     │   синоним в learned.yaml, только если значение есть в справочнике
                                                     │   или его одинаково исправили на ≥ 2 разных карточках;
                                                     │   остальное — кандидаты (outputs/learned_candidates.yaml)
                                                     ▼
              переобучение по алерту: prepare → build-gold → train-category / train-ner --distant → calibrate (dev)
                                                     ▼
              проверка до выкладки: attrx eval-real (dev), make report (holdout), make verify (сверка цифр)
~~~

Защита петли от ошибок модератора: одна опечатка («чорный») не становится каноном справочника. В справочник
попадает только значение, которое в нём уже есть, или одинаковое исправление минимум на двух разных карточках.
Повторный клик по той же карточке вторым голосом не считается. Расходящиеся правки одной формулировки тоже уходят
в кандидаты ([src/attrx/feedback.py](../src/attrx/feedback.py), `tests/test_hardening.py`). Запись в журнал
решений можно закрыть токеном (`ATTRX_TOKEN` → заголовок `X-Attrx-Token`), чтобы журнал, из которого учатся
словари, нельзя было пополнить анонимно.

## Пример на данных кейса (15.10)

| Поток против эталона (holdout, 2 416 карточек) | Что показал монитор |
|---|---|
| Сам holdout | алертов нет, PSI 0 |
| Демо-сэмпл `data/sample/real_cards.jsonl`, 400 карточек (`attrx demo`) | алерт PSI 0,43 «сильный»: сэмпл стратифицирован (по 60 смартфонов и ноутбуков), и generic в нём 30,5% против 43,2%. Новые листья в generic: накопительные водонагреватели (12), морозильные камеры (12), умные колонки (7). Качественные метрики в норме: review 3,8%, уверенность 0,94 |
| Те же 400 карточек без `category_id` и названия категории (cold start: решает классификатор) | неуверенная категория у 0,2% карточек, распределение то же. Классификатор (точность 0,9998) ассортимент холодного старта узнаёт |

## Ограничения

- Без эталона монитор видит только косвенные сигналы. Настоящую точность в продакшене измеряют выборочным аудитом:
  часть принятых значений отправляют в очередь модератора и считают долю подтверждённых. В журнале решений эти
  данные уже есть (`feedback`).
- PSI считается по категориям таксономии (12 + generic). Новые листья каталога внутри generic видны в списке
  `new_leaves`, но алерт по ним не поднимается: эталонный прогон покрывает лишь часть из 6 963 листьев.
- Пороги пока общие для всех категорий (меняются через `--threshold`). Раздельные пороги по категориям — следующий
  шаг после теневого режима.
