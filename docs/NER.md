# NER на distant supervision: модель для хвоста

ML-слой гибрида: токен-классификатор (BIO) на `cointegrated/rubert-tiny2`, обученный **без ручной разметки** —
метки получены сопоставлением значений каталога М.Видео с текстом карточек. Кейс просит начать с правил, затем
показать, что даёт ML; здесь — как строится разметка, как обучена модель и сколько она добавляет к правилам на dev.

Код: [`extractors/ner_distant.py`](../src/attrx/extractors/ner_distant.py) (разметка, датасет, калибровка),
[`extractors/ner.py`](../src/attrx/extractors/ner.py) (вид карточки, обучение, инференс). Тесты:
`tests/test_ner_distant.py` (разметка, без torch), `tests/test_ner_model.py` (модель, пропускается без torch/модели).

## 1. Зачем distant supervision

- **Ручная разметка дорогая**, а слабая разметка правилами учит модель только тому, что правила уже умеют.
- **В каталоге уже есть человеческая разметка**: характеристики YML-фида заполняет контент-команда М.Видео
  (241 тыс. карточек с эталоном, см. [EVALUATION.md](EVALUATION.md)). Если значение каталога встречается в тексте
  карточки, найденный фрагмент — бесплатная метка: «256 ГБ», «8/256», «6,75"», «черная», «Midnight», «Liebherr».
- **Результат**: 59 787 размеченных карточек train, 230 866 спанов, 28 атрибутов; сборка — 6 минут CPU.
  Это weak supervision из слайда 14 кейса, только источник меток — каталог, а не правила.
- **Утечки нет**: разметка строится только на train-сплите, калибровка — на отложенных 10% train,
  dev — только для оценки, holdout не используется.

## 2. Как строится разметка

Для каждой карточки train (категории таксономии + выборка generic для бренда, модели и цвета) и каждого атрибута
с эталоном ищутся все упоминания значения в `Card.full_text()` (название + описание + блок продавца):

| Тип значения | Как ищется | Пример |
|---|---|---|
| число с единицей | все написания единицы и пересчёт (`normalize.UNIT_PATTERNS`), разделитель тысяч | `256 ГБ` ~ `256GB` ~ `256Гб`; `1 ТБ` = 1024 ГБ; `5 000 мАч`; `139 см` = 55" |
| пара памяти | `RAM/накопитель`: ОЗУ — первое число, накопитель — второе с единицей | `12/256GB`, `16/1Tb` |
| число без единицы | только после названия атрибута; «-дюймовый» — спан из одного числа | `Диагональ: 6.7`, `6,7-дюймовый` |
| справочник | все синонимы, прилагательные в любом роде, английские названия | `черного`, `Black`, `Midnight` -> `чёрный` |
| бренд | написание vendor без учёта регистра, пробелов и дефисов | `Liebherr`, `Правила мебели` |
| модель | строка модели посимвольно (пробелы, дефисы, точки, слэши — любые) | `RB33A3440SA/WT` ~ `RB33A3440SAWT` |
| процессор | с производителем и без, семейство + номер | `Intel Core i5-12450H` ~ `Core i5 12450H` |

**Каждый спан проверяется функцией сравнения из метрик** (`eval.metrics.gold_matches`): если модель выдаст ровно
этот фрагмент, значение будет засчитано. Модель обрезается по соседним значениям: `Galaxy S26 Ultra 16/1Tb violet`
-> `Galaxy S26 Ultra`.

**Неоднозначность — консервативно.** Маска = токены не участвуют в loss: модель не учится ни «это атрибут»,
ни «это не атрибут».

- в названии другое значение того же атрибута (`черный/красный` при эталоне «черный») — атрибут карточки маскируется;
- во фрагменте описания и эталонное, и другое значение («есть черная и белая версии») — маска фрагмента;
- эталона в каталоге нет, а значение-кандидат в тексте есть (каталог неполный) — маска, а не «O»;
- «карты памяти до 1 ТБ», память видеокарты «RTX 4060 8GB», «50/60 Гц» — маска, а не метка;
- эталонное число без единицы и подписи (`185x60x65`) — маска;
- фрагмент подходит двум атрибутам (материал и цвет «нержавеющая сталь») — маска; бренд внутри другого значения
  (`Apple` в `Apple M3`) уступает ему; синоним бренда (`MacBook` -> Apple) — маска, а не метка бренда;
- мусорная «модель» каталога (`30x30см`) эталоном не считается.

**Вид карточки ≤ 256 токенов.** Короткая карточка (≤ 900 символов) подаётся целиком. Длинная — название плюс самые
информативные фрагменты (строки, предложения, пары блока продавца) в исходном порядке. Фрагмент оценивается по числу
с единицей, названию атрибута, значению справочника и «модельному» токену. Функция не знает эталона и одна и та же
при обучении и в пайплайне. Обрезано 61% карточек: в среднем 1 114 символов -> 776, медиана 186 токенов.
Вход модели — пара «название категории таксономии» + вид карточки.

### Пример: карточка `400452891` (train) и её BIO-разметка

```
Смартфон HUAWEI nova Y63 4/128GB Black
Смартфон Huawei Nova Y63 4/128GB Black выполнен в тонком пластиковом корпусе с диагональю 6,75".
• Аккумулятор 6000 мА*ч ... Цвет модели — черный.
```
Эталон каталога: бренд HUAWEI, модель `nova Y63`, накопитель 128 ГБ, диагональ 6,75, аккумулятор 6000 мА·ч, цвет чёрный.

| Токены | Метки |
|---|---|
| `Смарт` `фон` | O O |
| `H` `U` `A` `W` `E` `I` | B-brand I-brand I-brand I-brand I-brand I-brand |
| `no` `va` `Y` `6` `3` | B-model I-model I-model I-model I-model |
| `4` `/` | O O (ОЗУ у смартфона нет в схеме) |
| `128` `GB` | B-storage I-storage |
| `Black` | B-color |
| … `6` `,` `75` `"` | B-screen I-screen I-screen I-screen |
| `6000` `мА` `*` `ч` | B-battery I-battery I-battery I-battery |
| `черный` | B-color |

Токенизатор режет латиницу в верхнем регистре по буквам, поэтому спаны задаются по символам и переводятся в токены
по смещениям (`bio_labels`).

## 4. Модель и обучение

| Параметр | Значение |
|---|---|
| Энкодер | `cointegrated/rubert-tiny2`: 3 слоя, hidden 312, словарь 83 828, 29,1 млн параметров |
| Вход | пара «категория таксономии» + вид карточки, ≤ 256 токенов |
| Выход | 57 классов (O + B/I для 28 атрибутов); softmax только по меткам **схемы категории** карточки — при обучении и в пайплайне |
| Loss | кросс-энтропия по токенам, маски и служебные токены исключены |
| Оптимизация | AdamW, lr 1e-4, weight decay 0,01, разогрев 6% + линейное затухание, батч 32, 3 эпохи, seed 13 |
| Данные за эпоху | 71 574 примера: карточки таксономии ×2 (редкие атрибуты), generic ×1; 12,6 млн токенов |
| Железо | GTX 1060 6 ГБ (sm_61): `torch 2.14.1+cu126`, в сборке есть sm_60, его cubin исполняется на sm_61 (свежие сборки под CUDA 13 Pascal уже не поддерживают) |
| Время (v2) | разметка 6 мин (CPU) + обучение 13,6 мин (GPU, 6 711 шагов) + калибровка 10 с (GPU); всего на GPU с v1 — 24 мин |

**Почему GPU.** CPU этой машины — Pentium Gold G5400 без AVX, его делят несколько процессов: 8–13 с на батч,
то есть около 4 часов на эпоху. GPU берётся, только если torch поддерживает карту и свободно ≥ 2,5 ГБ видеопамяти
(`ner.pick_device`): карту делит локальная LLM. Иначе обучение идёт на CPU с `torch.set_num_threads(2)`.

**Декодирование.** Метка токена — argmax по меткам схемы категории. Сущность продолжается меткой I- того же атрибута
или продолжением слова и не переходит через перевод строки. Границы чинятся: число берётся целиком с единицей
(`6,|67 дюйма` -> `6,67 дюйма`), процессор — целиком (`Ryzen` -> `Ryzen 5 7520U`). На атрибут выдаётся одно
значение с максимальной вероятностью. Вероятность сущности — средняя по токенам P(B-a) + P(I-a).

**Что дали шаги.** Первая модель v1 обучена на 35,8 тыс. карточках, softmax по всем меткам, за 10,4 мин на GPU.

| Шаг | Где мерили | Результат |
|---|---|---|
| все сущности как есть (v1) | калибровочная часть train | доля верных значений 0,61 |
| + одно лучшее значение на атрибут + починка границ | там же | 0,90; диагональ 0,74 -> 0,98, процессор 0,85 -> 0,93 |
| + softmax по схеме категории при выводе | только NER на dev | macro-F1 0,423 -> 0,476; `battery_time` 0 -> 0,53 F1, `total_volume` 0 -> 0,34, `battery_life` 0 -> 0,26 |
| v2: 59,8 тыс. карточек, схема и в обучении, таксономия ×2 | только NER на dev | macro-F1 0,476 -> 0,513, P 0,913 -> 0,936; `bowl_volume` 0,36 -> 0,78, `load` 0,42 -> 0,64 |

## 5. Калибровка уверенности

Вероятность сущности переводится в P(значение верно) **изотонической регрессией** на отложенных 10% train
(3 303 карточки, 8 913 значений с эталоном; `md5("ner-calib:" + sku)`). В обучении эти карточки не участвуют.
Таблица строится по каждому атрибуту с ≥ 100 точками (brand, model, color, storage, screen, cpu, ram, type,
connection). Для редких атрибутов общая таблица умножается на сглаженную точность атрибута. Таблицы лежат
в `models/ner/attrx_ner.json` (`calibration`).

| Вероятность сущности | 0,6 | 0,8 | 0,9 | 0,95 | 0,99 |
|---|---:|---:|---:|---:|---:|
| P(верно): бренд | 0,85 | 0,91 | 0,97 | 0,98 | 0,99 |
| P(верно): накопитель | 0,90 | 0,97 | 0,99 | 0,99 | 0,99 |
| P(верно): цвет | 0,58 | 0,63 | 0,74 | 0,82 | 0,95 |
| P(верно): тип | 0,43 | 0,56 | 0,69 | 0,75 | 0,88 |
| P(верно): модель | 0,13 | 0,15 | 0,42 | 0,51 | 0,66 |

**Проверка на dev** (2 581 карточка, только NER, 7 859 значений с эталоном): точность 0,923, ECE 0,031.

| Калиброванная уверенность | 0,5–0,6 | 0,6–0,7 | 0,7–0,8 | 0,8–0,9 | 0,9–0,95 | ≥ 0,95 |
|---|---:|---:|---:|---:|---:|---:|
| значений | 401 | 237 | 452 | 2 055 | 1 047 | 3 667 |
| доля верных | 0,59 | 0,68 | 0,71 | 0,94 | 0,95 | 0,98 |

**Стыковка с агрегатором.** Кандидат NER получает `score` = P(верно) × качество нормализации. Значения с
P < 0,5 не выдаются. Агрегатор умножает score на вес источника `ml` = 0,9 и объединяет источники через noisy-OR.
В пайплайне NER отвечает только за слабые атрибуты, а там его точность ниже: 0,68 на 149 значениях dev, где значение
дал один NER. Поэтому общую калибровку пайплайна (`attrx calibrate`, `config/calibration.json`) нужно строить
с включённым `ml`: тогда у групп `ml|…` будут свои кривые (см. §6).

Небольшие потери (−0,005…−0,02 F1) есть у `air_fryer/model`, `tablet/ram`, `laptop/cpu`, `fridge/model`: значение NER
спорит со слабым значением правил, конфликт уводит слот на проверку.

**Справедливость** (F1 и recall на извлекаемых, правила -> + NER): маркетплейс 0,837 -> 0,843 (R_ext 0,921 -> 0,935,
новых значений 321 -> 371); М.Видео 0,851 -> 0,853. Редкие категории (tail) 0,799 -> 0,808 (R_ext 0,881 -> 0,902),
torso 0,808 -> 0,809, head 0,852 -> 0,856. Короткие описания 0,804 -> 0,808, средние 0,840 -> 0,845, длинные
0,889 -> 0,891. Больше всего NER помогает слабым сегментам: хвосту и маркетплейсу.

**NER на всех атрибутах хуже.** Если вызывать модель для всех атрибутов, а не только слабых (`LLM_ROUTE_THRESHOLD`
1,01), её значения спорят с верными значениями правил, и F1 падает до 0,816. Порог маршрутизации 0,6 оказался лучшим
по micro-F1 (0,7 -> 0,845, 0,8 -> 0,841, 0,9 -> 0,840). Поэтому NER остаётся моделью для хвоста, как и задумано
в гибриде кейса: правила для ядра, модели для хвоста.

## 7. Разбор ошибок (только NER, dev)

1. **Границы модели.** В модель попадают соседние слова: `JBLCLIP5RED красная` (эталон `JBLCLIP5RED`),
   `iPad Mini WiFi+Cell`. Бывает и так, что в названии вообще нет модели: `GPS трекер` при эталоне `AirTag`,
   `с циркулем школьная 115 мм` при артикуле `881091`. Это 253 из 557 неверных значений NER (включая отправленные
   на проверку); в пайплайне модель обычно берут правила.
2. **Соседняя величина вместо нужной.** Время работы с кейсом `25 часов` вместо 6 ч от одной зарядки; игровой режим
   `144 Гц` вместо 120 Гц; бак для воды `5 литров` вместо пылесборника 1,5 л; диагональ другой модели серии.
3. **Иерархия значений каталога.** `беспроводные` (Bluetooth) при эталоне `True Wireless`; `накладные` при
   `полноразмерные`; `капельное` размораживание холодильной камеры при `ручное` у морозильной.
4. **Цвет и варианты.** `Green` при эталоне `бирюзовый`, `Silver` при `серый`, описание перечисляет расцветки серии.
5. **Ошибки самого каталога.** Пылесборник `3,2 л` при эталоне 0,32; чайник 1,8 л при эталоне `1800`; ОЗУ планшета
   16 ГБ при эталоне 2. Модель права, метрика штрафует. Такие случаи идут в очередь модерации и в петлю обратной связи.

Ещё бывают процессоры новых линеек (`Core i5 120U` при эталоне `Intel Core 5 120U`) и обрывки (`Apple` вместо
`Apple M1 Pro`).

## 8. Ограничения

- **Шум каталога.** Неверные значения, неразобранные справочником и значения-«бакеты» попадают в разметку;
  консервативные маски шум уменьшают, но не убирают.
- **Редкие атрибуты.** Меньше 150 спанов — метки нет (`height`, `area`, `btu`, `case_material`, `cooling_power`).
  У `battery_life`, `depth`, `chambers` recall низкий.
- **Вид ≤ 900 символов.** Значение глубоко в длинном описании модель не видит; правила видят весь текст.
- **Слабые атрибуты — самые трудные.** В пайплайне точность значений, которые дал один NER, 0,68 против 0,92 у NER
  в целом. Поэтому калибровку пайплайна нужно строить с `ml`, а значения ниже порога уходят на проверку.
- **Проверка заземления** (`verify.py`) не пропускает бренды вне справочника (открытый словарь NER) и числа с
  разделителем тысяч (`5 000 мАч`). На dev отброшено 66 из 8 288 значений NER (0,8%), из них 55 — бренды вне
  справочника.
- **Скорость на CPU.** Без AVX — 16 карточек/с у NER и 32 у пайплайна. На GPU — 190–380 и 190–220.
- **Модель не в git** (115 МБ, `models/` в `.gitignore`). Без модели или без `[ml]` слой выключен: пайплайн работает,
  `NerExtractor.load` возвращает `None` без импорта torch.

## 9. Как переобучить

```bash
export PATH="$HOME/.local/bin:$PATH"
# torch: для GTX 10xx (Pascal) — сборка cu126; CPU-сборка тоже подойдёт, но медленно
uv pip install -p .venv/bin/python "torch==2.14.1" --index-url https://download.pytorch.org/whl/cu126
uv pip install -p .venv/bin/python -e ".[ml]"
attrx prepare && attrx build-gold                  # data/processed/*.parquet, эталон
attrx train-ner --distant --dry-run                # только разметка и статистика -> data/processed/ner_distant_stats.json
attrx train-ner --distant                          # 60 тыс. карточек, 3 эпохи, GPU при ≥ 2,5 ГБ свободной памяти -> models/ner
# оценка на dev: правила / + NER / только NER
attrx eval-real --sources seller,rules             --out data/processed/ner_base.json
NER_DEVICE=cuda attrx eval-real --sources seller,rules,ml --out data/processed/ner_hybrid.json
NER_DEVICE=cuda attrx eval-real --sources ml              --out data/processed/ner_only.json
NER_DEVICE=cuda attrx calibrate --sources seller,rules,ml          # калибровка пайплайна с NER
```

Параметры `train-ner --distant`: `--max-examples` (60 000), `--generic` (48 000), `--tax-oversample` (2),
`--epochs` (3), `--lr` (1e-4), `--min-spans` (150), `--device auto|cpu|cuda`, `--threads` (2), `--seed` (13).
Модель пишется во временную папку и подменяет `models/ner` целиком. Предыдущая версия остаётся в `models/ner.prev`.
Инференс: `NER_DEVICE` (`cpu` по умолчанию, `cuda`), `NER_THREADS` (2), `ML_MODEL_PATH`, `ML_ENABLED`.
