# Финальная презентация

Финальная защита — 31.10 (жюри: продуктовая ценность, реалистичность внедрения, питч); до этого — технический чекпоинт
23.10. Презентация — один из шести обязательных артефактов кейса («подход, метрики, выводы»), её читает и LLM-ревью
репозитория. Все цифры — holdout, отчёт v2 (`submission/`; основной набор — весь holdout, 23 391 карточка); синтетики нет.

- **Слайды:** [slides.pdf](slides.pdf) (13 слайдов, 16:9) и [slides.html](slides.html) — клавиши ← → / пробел, `O` — обзор,
  `F` — полный экран, `1–9` — слайд по номеру (дальше — `#10`…`#13` в адресе).
- **Генератор:** [slides.py](slides.py) читает `submission/*.json` (метрики, лестница, сегменты, калибровка, порог,
  стоимость; наборы `compare.json` — `full_holdout`, `stratified`, `llm_subsample`), `config/taxonomy.yaml`
  и `docs/checkpoint/demand_stats.json`; дизайн-система, навигация и схема пайплайна — из
  [checkpoint/concept.html](checkpoint/concept.html). Числа, которых нет в JSON сдачи, вынесены в константы
  с источником: подвыборка LLM и карточки вне фида (`LLM`, `COLD` — `submission/REPORT.md` §4, §11), новые названия
  (`TITLES` — §5), весь dev и кандидат исправления калибровки (`DEV_FULL_F1`, `CAND` — [EVALUATION.md](EVALUATION.md)
  §9.2, §9.5), база «было» для сегментов (`BASELINE_DEV` — §8.4).
- **Пересобрать** (из корня репозитория):

```bash
.venv/bin/python docs/slides.py
chromium --headless --no-sandbox --disable-gpu --no-pdf-header-footer --print-to-pdf=docs/slides.pdf "file://$PWD/docs/slides.html"
```

## Правила для цифр

- Главные цифры — весь holdout (основной набор отчёта v2): правила, словари, NER, калибровка и порог на нём
  не настраивались. Стратифицированный набор и подвыборка LLM — вторичные таблицы, с подписью. Dev — только с подписью
  (база «было», выбор порога, кандидат исправления калибровки).
- Precision, recall и F1 — по каждому атрибуту и категории; общую accuracy не показываем.
- Recall дважды: полный и по значениям, которые есть в тексте. Покрытие — с `new_fills` против неполного эталона.
- Честно показываем невыполненное и слабое: LLM зовётся для 31 % карточек при цели ≤ 20 %; на проверку уходит 10,8 %
  слотов при цели ≤ 10 %; у самого порога уверенность завышена (слой 0,70–0,80 верен на 57 %) — кандидат исправления
  найден только на dev и не применён; на 4B-модели LLM не добавляет F1.
- Числа форматируются как в `REPORT.md`: значения JSON (4 знака) без повторного округления «вверх».
- У каждой цифры — источник в подвале слайда.
