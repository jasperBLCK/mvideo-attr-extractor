ATTRX — ХАРАКТЕРИСТИКИ ТОВАРОВ ИЗ ТЕКСТА КАРТОЧКИ, С ЦИТАТОЙ И УВЕРЕННОСТЬЮ

Кейс № 3 М.Видео «ИИ для автоматического заполнения характеристик товаров». Команда «Ъыъ»: Makhkets, jasperBLCK.

attrx читает текстовую карточку товара (название, описание, атрибуты продавца), определяет категорию и её обязательные атрибуты, извлекает значения, приводит их к каноническому виду и для каждого значения возвращает калиброванную уверенность, статус и цитату из карточки. Надёжное идёт в каталог, сомнительное — модератору, а правки модератора пополняют словари. Ничего не выдумываем: нет цитаты — нет значения, значение только от LLM — всегда на проверку.

▌ РЕЗУЛЬТАТ НА HOLDOUT
Весь отложенный сплит каталога М.Видео с эталоном — 23 391 карточка (без 400 SKU демо-сэмпла; 94% — хвост каталога: бренд, модель, цвет). Правила, словари, NER, калибровка и порог на нём не настраивались. Отчёт v2: исправления после первого прогона выбраны только на dev, v1 раскрыт (submission/REPORT.md, docs/EVALUATION.md §9). Режим в сдаче — «+ NER».
- Точность значений, принятых в каталог автоматически, — 0,954 (95% ДИ от 0,952) при пороге 0,70, выбранном на dev под ≥ 0,95; принимается 94% найденного.
- micro P / R / F1 = 0,954 / 0,779 / 0,858; полнота по значениям, которые есть в тексте, — 0,927 (в тексте есть 83% эталона); F1 с учётом поискового спроса — 0,937; macro-F1 по атрибутам 0,640.
- Каталог полнее: слоты 80,7% → 88,1% (+5 488 значений там, где в каталоге пусто); доля поискового спроса с заполненным атрибутом 95,7% → 97,2%. Карточки вне фида (75% каталога): автоматически заполняется 54,3% слотов.
- Справедливость: F1 М.Видео 0,873, маркетплейс 0,853 (в базовой линии 0,654 и 0,447); крупные / средние / редкие категории 0,870 / 0,844 / 0,818. Новые названия (нет в train, 72% карточек): F1 0,841 против 0,912 у повторов.
- Без category_id (категорию выбирает классификатор) F1 тот же — 0,842 на стратифицированном наборе из 2 416 карточек: категория угадана у всех.
- Обязательные поля кейса: бренд, модель, память смартфона — F1 0,99–1,00; поля ноутбука — 0,89–0,98.
- Лестница подходов: правила F1 0,853 → + NER 0,858; весь dev → весь holdout 0,859 → 0,858 — без переобучения.
- Калибровка: ECE 0,019. Рабочий порог 0,70 (точность принятых 0,954). Для категорий, где ошибка дороже покрытия, — строгий режим, порог 0,82: на dev точность принятых 0,982 при доле автопринятия 85,5% вместо 94%. Слабое место рабочего порога честно показываем: принятые значения с уверенностью 0,70–0,80 верны в 57% случаев (4% принятого, 91% — цвет и модель хвоста); строгий режим отсекает именно их. В сдаче оставили 0,70: порог выбран на dev до holdout, протокол не нарушаем.
- LLM (локальная qwen3:4b-instruct, подвыборка 662 карточки): вызывается для 31% карточек, 3,3 с на вызов; F1 0,849 с LLM и без; 61 ответ без опоры в тексте отброшен; из значений, которые нашла только LLM, верны 38% — поэтому они идут модератору как подсказки, а не в каталог. Следующий шаг — тот же замер с моделью организаторов на ВМ.
- Стоимость 1000 карточек: гибрид — 0,83 ₽ на своей GPU, 20,6 ₽ через GigaChat Lite, 63,2 ₽ через YandexGPT Lite против 5,6 / 84,6 / 260,2 ₽ у «LLM на каждую карточку» (в 4–7 раз дешевле); режим в сдаче без LLM — меньше 0,01 ₽.
- Предсказания по каждой карточке: submission/predictions.csv и predictions.jsonl.

▌ ЗАЧЕМ ЭТО М.ВИДЕО
- Пустая характеристика выводит товар из фильтров и атрибутной выдачи: меньше показов, кликов и GMV.
- 56,5% из 30 991 350 кликов поиска — по запросам, где покупатель назвал атрибут, 24,9% — характеристику кроме бренда и модели: «игровые ноутбуки» — 88 336 кликов, «телевизоры 55» — 61 792.
- У 75% из 1 177 200 карточек нет ни оффера, ни категории — только текст; блок «Характеристики» от продавца есть лишь у 6,6% карточек с эталоном.

▌ КАК УСТРОЕНО: ДЕШЁВОЕ — НА ЯДРО, ДОРОГОЕ — НА ХВОСТ
1. Категория: из id каталога, иначе классификатор по тексту (TF-IDF + линейная модель «раздел → лист»): на holdout 0,9998 против 0,921 у ключевых слов.
2. Атрибуты продавца, правила и словари: числа с единицами, 4 822 бренда каталога с транслитерацией, цвета RU/EN, «8/256». CPU, ~1 500 карточек/с на ядро.
3. Только для пустых, слабых или конфликтных атрибутов — NER (ruBERT-tiny2, обучен без ручной разметки на значениях каталога, найденных в тексте) и затем LLM в контуре — только об атрибутах, упомянутых в тексте.
4. Нормализация к канону: единицы, числа, синонимы, справочники допустимых значений.
5. Уверенность: noisy-OR источников и калибровка «уверенность → вероятность, что значение верно»; выше порога 0,70 — accepted, ниже — review, нет в тексте — missing.
6. Петля обратной связи: правка модератора → outputs/feedback.jsonl → attrx learn → новые синонимы в словарях.

▌ ЗАЩИТА ОТ ГАЛЛЮЦИНАЦИЙ
- Строгий JSON по схеме категории, temperature 0; допустимые значения — в промпте, значение вне справочника отбрасывается.
- Цитата обязательна; проверка заземления (src/attrx/verify.py): цитата выравнивается с текстом карточки, значение должно из неё следовать.
- Значение, которое предложила только LLM, никогда не принимается автоматически — статус «на проверку» (pipeline.UNVERIFIED_ONLY, tests/test_grounding.py); подтверждая продавца, правила или NER, LLM повышает уверенность.

▌ ВНЕДРЕНИЕ
- Теневой режим 2–4 недели → автопринятие выше порога в топ-категориях по трафику → все категории; падает precision — категория возвращается в тень.
- Интеграция с PIM: POST /api/extract/batch (до 1000 карточек за запрос) или attrx extract по выгрузке.
- LLM — любой OpenAI-совместимый endpoint: vLLM или Ollama в контуре, GigaChat или YandexGPT без VPN. Без LLM работают правила, словари, классификатор категории и NER (extra [ml]).

▌ ИНТЕРФЕЙС МОДЕРАТОРА
Очередь на проверку (сначала то, что чаще ищут и в чём система сомневается), подсветка цитаты, правка в один клик. Generative UI: экран собирается под запрос из фиксированного набора компонентов, значения — из результата пайплайна.

▌ СТЕК
Python 3.11, pydantic, FastAPI, pandas, pyarrow, DuckDB, rapidfuzz, PyYAML, numpy, scikit-learn (обучение классификатора категории). NER — PyTorch, transformers, ruBERT-tiny2 (extra [ml]). LLM — клиент openai к OpenAI-совместимому API, SQLite-кэш. UI — HTML, CSS и JS без сборки. Docker, pytest, ruff, CI.
