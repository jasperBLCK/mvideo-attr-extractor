Четыре роли, одна работа: товар должен находиться по характеристикам

Контент-менеджер каталога

Когда приходит партия карточек, хочу проверять только сомнительные значения — с цитатой перед глазами, чтобы за смену пропустить больше SKU и не пустить ошибку в фильтры.

Что даёт attrx
  • очередь «на проверку»: сначала то, что чаще ищут; с цитатой
  • правка в один клик → синоним в словаре
Метрика ролиSKU в час на модератора; доля значений без ручной правки

Категорийный менеджер

Когда развиваю категорию, хочу видеть, каких фильтров не хватает и сколько поиска они теряют, чтобы закрывать дыры там, где ищут.

Что даёт attrx
  • заполненность атрибутов с весом поискового спроса
  • новая категория — сразу с предложениями на проверку
Метрика ролиcoverage обязательных атрибутов, взвешенный трафиком

Продавец маркетплейса

Когда загружаю ассортимент, хочу не заполнять десятки полей руками, чтобы товар быстрее прошёл модерацию и начал продаваться.

Что даёт attrx
  • характеристики из описания, которое продавец уже написал
  • список того, чего в карточке нет
Метрика ролидоля карточек, принятых с первого раза; время до публикации

Поиск, рекомендации, матчинг

Когда строю фильтры, ранжирование и склейку одинаковых SKU, хочу полные канонические значения с уверенностью, чтобы выбрать порог под свою задачу.

Что даёт attrx
  • канон: единицы, синонимы, справочник
  • confidence у каждого значения; API и батч
Метрика ролиprecision принятых значений; доля SKU в фильтрах

Единица ценности одна: верно заполненная характеристика, по которой ищут. attrx встаёт в PIM и модерацию через API и батч.

Решение · гибридный пайплайн

Ядро закрывают дешёвые правила. LLM — только для остатка и только с цитатой

Категория и правила

Без id категорию даёт классификатор (0,9998). Ядро — числа с единицами, 4 822 бренда каталога, цвета: CPU, бесплатно.

NER

ruBERT-tiny2 на разметке из каталога. Только слабые атрибуты — не портит то, что закрыли правила.

LLM

Холодный старт и остаток, только об упомянутых атрибутах. On-prem или РФ-облако, кэш, лимиты.

Заземление и порог

Решает проверка: цитата найдена в тексте, значение следует из неё; порог 0,70; одна LLM — на проверку.

Весь holdout, 23 391 карточка: правила F1 0,853 → + NER 0,858 (полнота по извлекаемому 0,918 → 0,927) при точности 0,954. На подвыборке 662: + LLM 0,849 = + NER 0,849 — значения одной LLM уходят на проверку.

Схема = src/attrx/pipeline.py; порог 0,70 — config/calibration.json (attrx calibrate); в хвост — уверенность < 0,6 (LLM_ROUTE_THRESHOLD); holdout — submission/compare.json04 / 09

Внедрение и экономика

В прод — через тень: автопринятие только выше порога, LLM внутри контура

Шаг 0

Офлайн-оценка

Holdout эталона, разбор ошибок по атрибутам и сегментам.

Гейт: P ≥ 0,95 у автопринятых
Шаг 1

Тень, 2–4 недели

Пишем предсказания рядом, не в каталог; сверяем с правками модераторов, калибруем порог по категориям.

Шаг 2

Автопринятие

Выше порога — в PIM в топ-категориях по трафику; остальное — в очередь. Выборочный аудит каждый день.

Шаг 3

Все категории

Холодный старт через LLM со статусом «на проверку»; правки дообучают NER и словари.

Интеграция с PIM. POST /api/extract/batch (до 1000 карточек) или attrx extract по выгрузке. Принятое — запись в PIM, «на проверку» — в очередь модерации.

Данные не покидают контур. LLM — любой OpenAI-совместимый endpoint: vLLM / Ollama on-prem, GigaChat / YandexGPT без VPN. Без LLM работают правила, словари и классификатор.

Мониторинг и откат есть. attrx monitor: доля «на проверку» и «нет в тексте» по категориям, PSI категорий, доля вызовов LLM → алерт с действием. Выборочный аудит — в пилоте; precision ниже гейта — категория возвращается в тень.

Скорость. Правила — ~1 500 карточек/с на ядро, с NER — 421 на GPU (весь holdout, медиана 3 замеров). LLM — 3,3 с на вызов, поэтому хвост в проде — асинхронно план.
