Проблема

  • Карточки от продавцов шумные: характеристики в свободном тексте, разные единицы и синонимы
  • Не заполнен атрибут → товара нет в фильтре → ниже CTR и конверсия
  • Ручное заполнение медленное и дорогое, а ошибки попадают в поиск
Цель: заполнить обязательные атрибуты автоматически и ничего не выдумать
2
attrx

Решение

Карточка→Категория→Продавец→Правила→NER→LLM→Проверка цитаты→Уверенность→accepted / review / missing
  • Дешёвые источники закрывают ядро, модели работают только на хвосте
  • У каждого значения есть уверенность, источник и цитата из карточки
  • Сомнительные значения уходят модератору, его правки пополняют словари

Анти-галлюцинации

  • LLM обязана вернуть дословную цитату (strict JSON schema)
  • Проверка заземления: цитата есть в карточке, значение из неё следует, enum-значение есть в справочнике
  • Конфликт продавца и текста → статус review, альтернативы показываются модератору
  • Generative UI: модель выбирает компоненты, значения берутся из результата, а не из её ответа

Generative UI

Интерфейс собирается под запрос модератора: «покажи только то, что надо проверить, с цитатами».

LLM возвращает декларативный UISpec из 7 разрешённых компонентов. Его валидирует pydantic, рендер идёт без innerHTML.

Без LLM работает детерминированный шаблон.

Метрики, которые мы считаем

  • Precision / Recall / F1 по каждому атрибуту и категории
  • Coverage: доля заполненных атрибутов
  • Traffic-weighted F1: важнее атрибуты, по которым фильтруют
  • Кривая precision/coverage от порога → выбор CONFIDENCE_THRESHOLD под целевую точность

Внедрение без VPN

  • Без LLM всё работает на правилах и NER на CPU: один Docker-контейнер
  • LLM через любой OpenAI-совместимый endpoint: on-prem vLLM/Ollama, GigaChat, YandexGPT
  • Кэш и лимит вызовов: LLM платим только за хвост
  • Интеграция: POST /api/extract/batch из PIM или CLI по выгрузке
