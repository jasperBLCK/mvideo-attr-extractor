# Отчёт v2: извлечение характеристик на holdout каталога М.Видео

v2 (после исправлений, найденных на dev и на демо-сэмпле вне eval-набора; eval-набор для выбора исправлений не использовался). Реальный каталог М.Видео, отложенный сплит holdout: при настройке правил, словарей, калибровки и порога не использовался. Эталон — характеристики YML-фида; вход — текст карточки и id категории каталога. Режим в сдаче — «+ NER».

Карточек: **23 391** — весь holdout с эталоном, кроме 400 SKU демо-сэмпла; режим в сдаче **+ NER**, порог автопринятия **0,70**.

## Главное

- **Весь holdout (23 391 карточек): P / R / F1 = 0,954 / 0,779 / 0,858**, recall на значениях, которые есть в тексте, 0,927 (в тексте есть 83,0% эталона), F1 с учётом спроса 0,937.
- **Точность принятых значений 0,954** (95% ДИ от 0,952) при пороге 0,70; принимается 94,0% найденных значений, остальное — модератору.
- Стратифицированный набор (2 416 карточек — те же, что в v1): P / R / F1 = 0,961 / 0,749 / 0,842, точность принятых 0,961. На всём holdout точность ниже: 94,1% карточек — хвост (generic), где цвет и модель — самые трудные ячейки.
- Скорость (медиана 3 замеров после прогрева, одна машина): правила 1235 карт./с на ядро, «+ NER» 382 карт./с (NER на GTX 1060); стоимость — раздел 12.
- Каталог полнее: слоты 80,7% → **88,1%** (+5 488); доля поискового спроса, по которой атрибут заполнен, 95,7% → **97,2%**.
- Справедливость: М.Видео 0,873, маркетплейс 0,853; head / torso / tail — 0,870 / 0,844 / 0,818.
- Новые названия (дословно нет в train): F1 0,841 на 16 803 карточках против 0,912 на уже встречавшихся.
- Без category_id (категорию выбирает классификатор по тексту): F1 0,842 против 0,842 с ним; категория таксономии угадана у 100,0% карточек.
- **Слабое место — калибровка у порога:** принятые значения с уверенностью 0,70–0,80 (4,1% принятых) верны на 0,569 при обещанных 0,751; это 865 из 2 270 неверных принятых, 91% слоя — ячейки хвоста (раздел 9).
- LLM (qwen3:4b-instruct) на подвыборке 662 карточек: F1 0,849 → 0,849; значения только от LLM — на проверку.

- протокол: скорость — медиана 3 замеров после прогрева на 50 карточках (в v1 первый режим платил за ленивую загрузку); основная таблица — весь holdout; срезы «новые названия» и «без category_id»; рабочая точка ровно на пороге в threshold.json; выгрузка стратифицированного набора для `attrx verify`

## 1. Набор и протокол

- **Основной набор — весь holdout с эталоном** (23 391 карточек, без 400 SKU демо-сэмпла): максимум карточек на категорию. Состав — как в каталоге, поэтому хвост (generic) — большинство.
- **Стратифицированный набор** (2 416 карточек: все 1 372 карточек категорий таксономии + 1 044 карточек хвоста по полосам размера) — тот же, что в v1, для сравнения версий; выгружен в `data/sample/holdout_eval_cards.jsonl` + `holdout_eval_gold.jsonl`.
- **Что получает пайплайн:** название, очищенное описание, блок «Характеристики» продавца и **id категории каталога** (`category_id`, как у карточки в листинге каталога; название категории используется, только если id нет). Характеристики фида (`vendor`, `model`, `param`) в пайплайн не подаются. Имя продавца передаётся, но в извлечении не участвует (только для разрезов). Отдельный прогон без `category_id` — раздел 3.
- **Holdout:** правила, словари (train), NER (train), калибровка и порог (dev) заморожены до прогона; режим в сдаче — по правилу, заданному до прогона («+ NER», если не теряет > 0,005 точности и не хуже по F1).

## 14. Ограничения и честность оценки

- **Эталон — каталог:** ошибки контент-команды засчитаны как наши ошибки (процессор «AMD HX 370» без линейки, MacBook 13" при эталоне 13,6, модель «Телевизор смарт»).

- **Карточки с эталоном — карточки фида:** для карточек вне фида показано только покрытие.
