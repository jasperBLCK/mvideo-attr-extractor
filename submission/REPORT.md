# Отчёт: извлечение характеристик на holdout каталога М.Видео

Реальный каталог М.Видео, отложенный сплит holdout: при настройке правил, словарей, калибровки и порога не использовался и посчитан один раз. Эталон — характеристики YML-фида, вход — только текст карточки. Режим в сдаче — «+ NER».

Карточек: **2 416** (категории таксономии — 1 372, хвост каталога — 1 044), режим в сдаче: **+ NER**, порог автопринятия **0,69**.

## Главное

- **Точность принятых значений 0,959** (95% ДИ от 0,955) при пороге 0,69, выбранном на dev под точность ≥ 0,95; автоматически принимается 94,4% найденных значений, остальное — модератору.
- micro P / R / F1 = **0,960 / 0,752 / 0,843**; recall на значениях, которые есть в тексте карточки, — **0,934** (в тексте есть только 79,0% эталона: это потолок «только из текста»).
- F1 с учётом поискового спроса **0,938**, macro-F1 по атрибутам 0,651, по ячейкам «категория × атрибут» 0,777.
- Каталог становится полнее: слоты схемы 89,7% → **93,2%** (+403 значений там, где в каталоге пусто); доля поискового спроса, по которой атрибут заполнен, 95,6% → **97,1%**.
- Справедливость: F1 М.Видео 0,853 и маркетплейс 0,830; head / torso / tail — 0,853 / 0,784 / 0,836.
- Скорость: 1268 карточек/с на одном ядре без моделей; с NER на GPU — 393 карточек/с.
- LLM (локальная qwen3:4b-instruct) на подвыборке 662 карточек: F1 0,850 → 0,850, LLM вызывается для 31,0% карточек; значения только от LLM идут на проверку, а не в каталог.

## 1. Набор и протокол

- **Набор:** все карточки сплита `holdout` с эталоном в 12 категориях таксономии и 1 000 карточек хвоста каталога (generic), стратифицированных по размеру категории — так же, как на dev (`attrx eval-real`).
- **Исключены 400 SKU** `data/sample/real_cards.jsonl`: на них показывали демо и мерили LLM-бенчмарк; в честную оценку они не входят.
- **Holdout посчитан один раз** после того, как правила, словари (бренды, соответствие справочников, стиль моделей — по train), NER (train) и калибровка с порогом (dev) были заморожены. Режим в сдаче выбран правилом, заданным до прогона: «+ NER», если он не теряет точность больше 0,005 и не хуже по F1.
- **Метрики:** P/R/F1 — только по слотам, где эталон есть; значение там, где в каталоге пусто, — дозаполнение (`new_fills`), а не ошибка; числа сравниваются с допуском 1%, бренды и модели — без регистра и пунктуации, цвета — по базовой палитре (docs/EVALUATION.md).
- **LLM — на подвыборке** 662 карточек (≥ 150 смартфонов и ноутбуков, остальные категории и хвост пропорционально): на этой же подвыборке прогнаны все четыре режима, поэтому прирост от LLM честный.

**Что LLM даёт модератору.** Значений только от LLM (на проверке): 71, из них 23 закрывают слот, пустой без LLM; где есть эталон (34), верны 38,2%. Если бы такие значения принимались автоматически (без инварианта доверия), было бы P / R / F1 = 0,958 / 0,764 / 0,850 против 0,962 / 0,761 / 0,850: полнота растёт, но ценой точности каталога — поэтому одна LLM только предлагает, решает человек.

«Спрос» — доля поискового спроса, по которой атрибут заполнен: слоты взвешены долей кликов категории × долей запросов, где покупатели называют этот атрибут (config/traffic_weights.yaml). В наборе (holdout) у всех карточек есть оффер в фиде, поэтому каталог уже заполнен на ~90%; основной эффект — на карточках вне фида.

**Cold start — карточки вне фида** (1 000 карточек того же сплита без оффера, эталона нет; таких в каталоге 75%): категория из таксономии у 10,8% (классификатор по тексту; неуверенная категория — 0,0% карточек), автоматически заполняется 54,4% слотов схемы, на проверку — 11,5%; 252 карточек/с. Точность на них не измерить (эталона нет) — значения уходят в каталог по тому же порогу и попадают в выборочную проверку модератором.

## 11. Разбор ошибок

Всего строк: 2 938 — неверных значений 324, пропусков 2 211, значений там, где в каталоге пусто (дозаполнение, не ошибка) 403; в `errors.csv` — 2 938 строк (колонка `extractable` — есть ли эталонное значение в тексте карточки).

Из 2 211 пропусков **1 801 — значения нет в тексте карточки** (потолок «только из текста»), 337 — значение найдено, но уверенность ниже порога (очередь модератора), 72 — значение в тексте есть, но не найдено.

Больше всего неверных принятых значений: generic/color — 62, generic/model — 29, headphones/connection — 20, headphones/type — 14, fridge/no_frost — 12, tv/os — 9, smartphone/color — 9, smartwatch/color — 9.
Чаще всего не найдено (значение в тексте есть): fridge/chambers — 12, fridge/total_volume — 7, fridge/height — 6, tablet/screen — 4, headphones/battery_life — 4, generic/model — 4, vacuum/dust_volume — 3, washing_machine/spin — 3.

Классы ошибок (подробно — docs/EVALUATION.md §8.5 и §9): значения нет в тексте карточки (основная часть пропусков — потолок «только из текста»); значение найдено, но уверенность ниже порога (очередь модератора); соглашения каталога, которых нет в тексте (тип наушников, цвет узора), и ошибки самого эталона.

## 12. Ограничения и честность оценки

- **Эталон — каталог, а не ручная разметка:** контент-команда М.Видео иногда ошибается (модель «Телевизор смарт», процессор «AMD HX 370» без линейки, MacBook 13" при эталоне 13,6); такие расхождения засчитаны как ошибки, поэтому реальная точность выше измеренной.
- **Потолок «только из текста»:** 79,0% эталонных значений вообще есть в тексте карточки; recall на них — 0,934, общий recall ограничен этим потолком. Выдумывать отсутствующие характеристики кейс запрещает.
- **Holdout использован один раз**, после заморозки правил, словарей, NER, калибровки и порога; после прогона ничего не подстраивалось.
- **Исключены 400 SKU сэмпла** (демо и бенчмарк LLM), поэтому карточек категорий таксономии меньше, чем в holdout целиком.
- **LLM — на подвыборке** 662 карточек и на одной локальной GPU (4B-модель): прирост и стоимость — оценка для этого стенда; в продакшене модель сильнее и быстрее (docs/LLM.md).
- **Карточки с эталоном — карточки фида:** блок «Характеристики» продавца у них редок (7%), поэтому оценка в основном меряет извлечение из названия и описания; для карточек вне фида показано только покрытие.

## Файлы

- `predictions.jsonl` (3,9 МБ) — полный ExtractionResult на каждую карточку набора; `predictions.csv` (0,8 МБ) — то же плоско, все карточки.
